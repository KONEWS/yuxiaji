# 月下集备份与恢复

入口：账户安全 → 备份与恢复。

## 使用

- **创建完整备份**：保存收藏、画廊图片关联、网盘链接、设备藏品、站点偏好、放送计划，以及这些记录引用的本站上传图片。完成后可下载标准 ZIP；关闭页面也不会丢失进度，可从历史记录继续，后台定时器也会推进。
- **自动备份**：默认开启，每天北京时间 04:00 创建一份，默认保留 14 天。界面可关闭或改为 7/14/30 天。首次启用会在下一次定时检查时创建首份备份。
- **离线恢复**：选择本站导出的 ZIP；大型备份会按每包最多 400 张不同图片自动分包，恢复时同时选中全部分包。浏览器先检查文件目录、长度和 CRC，再逐张上传，服务端验证图片 SHA-256、大小和真实格式。数据不会在上传阶段写入业务表。中断后可重新选择同一 ZIP，已经验证的图片可复用。
- **恢复历史备份**：先预览当前和备份的记录数量，明确确认替换。恢复会删除当前业务表中备份里不存在的记录；账户、登录会话、授权与密钥保留。执行前必须完成当前数据和图片的独立备份。
- **仅收藏 JSON**：保留旧版导出/合并导入。它只包含收藏及图片地址，不含图片文件、设备或站点偏好；导入会新增/更新条目，不按缺失记录删除。仍兼容旧文件。

## 包含与边界

完整备份白名单：`user_subjects`、`user_subject_images`、`media_storage_links`、`user_devices`、`user_state` 的业务偏好字段、`anime_airing_schedule`。角色标签、设备构图参数和自定义放送计划都会保留。历史来源字段支持每行一个地址，导出与恢复保留原有换行和空白。`user_state.anime_json` 等废弃字段不作为媒体来源。

不读取账户密码、会话、OAuth Token、第三方密钥或 Agent 审计表。外部封面 URL 与 MEGA 等网盘链接保留为链接；远端原图由原有归档流程管理，不通过网站下载第三方原图。缺失的本站图片会令备份明确失败，不能伪装成完整成功。

当前生产 R2 桶 `yuexiaji-assets` 的 r2.dev 访问关闭且没有公开自定义域名。备份保存在私有前缀 `backups-v2/<用户标识的SHA-256>/`，所有网页下载、导入与恢复都要求管理员 Session，并保留现有 CSRF 检查。不得为此桶开启公开访问；如需要公开媒体桶，应先将备份迁往独立私有桶。

这是同一 Cloudflare 账户内的备份；下载 ZIP 后另存到本地或网盘，才能在账户和整个桶同时不可用时恢复。开启自动备份并完成百度授权后，首次复制最近已完成的定时快照，再按快照日期每隔五天复制一份。目标为「我的应用数据／备份／月下集备份」。ZIP 文件名含日期与分包号，恢复时同时选择同一日期的全部 ZIP。

## 百度网盘授权入口

在「账户安全 → 备份与恢复 → 网盘连接」展开百度网盘。首次连接：

1. 前往 [百度网盘开放平台](https://pan.baidu.com/union)，申请有网盘权限的应用。
2. 把面板显示的完整 OAuth 回调地址登记到百度应用（使用实际登录站点的域名，路径为 `/api/backup/providers/baidu`）。
3. 在面板填写 AppKey、SecretKey，点击「授权百度网盘」；在百度官方页面登录并授权，自动回到安全设置。
4. 授权成功后显示「已授权」，过期可点击「重新授权」复用已加密保存的应用配置。解绑只移除本站凭据，不删除任何网盘文件。

复用既有 `external_service_credentials` 表和 Worker 凭据加密密钥；无需数据库迁移。OAuth state 绑定当前管理员 Session、有效期十分钟且只能使用一次。仅保存加密的应用凭据和 Token，不将密钥放进源码、响应、备份或日志。任务会在到期前刷新令牌，并在百度确认全部分包后记为完成。可以在网盘连接面板查看进度与最近错误。实际应用申请和百度在线授权需由管理员完成。

## 完整性和失败处理

- 数据导出通过同一次 D1 batch 读取相关表；清单带规范化数据 SHA-256，每张图片带 SHA-256 和 CRC32。图片内容相同会共享备份文件，但恢复时保留不同原对象的身份与不同画廊地址。
- 旧 JSON 导入和完整恢复都在单次 D1 batch 中提交。明确的 SQL 错误会整批回滚；网络响应丢失标为结果未知，不虚报回滚或自动重复覆盖。
- 确认恢复前再次比较预览版本，并在同一数据库事务开头验证当前表内容。其他页面或 Agent 修改过数据时拒绝覆盖，要求重新预览。
- 恢复图片先写到新的不可变位置；条件创建防止版本碰撞。全部图片验证成功后才切换数据库引用，不先覆盖当前图片。头像、背景新版本也使用不可变对象；旧固定键继续兼容读取。
- 恢复前快照独立持久化，错误响应带该备份编号。旧 JSON 失败响应中的 `preImportBackup` 会被前端保留并提供下载。
- R2 操作使用带续租的条件写锁；进度记录另用 ETag 条件写，旧请求不能覆盖新进度。后台处理按小批次推进，同一天的图片处理失败最多连续重试三次。创建快照前的校验或数据库错误也会记录并显示，后续定时检查会重试，成功后清除错误提示。

## 文件与任务

- `records/<id>.json`：完整数据清单、图片引用和进度，只有 `complete` 可下载/恢复。
- `blobs/<sha256>`：去重后的图片备份，与在线展示图独立；按已保留备份的引用清理过期孤立文件。
- `cache/`：源图片版本到已验证备份的索引；同时匹配对象 ETag 和上传时间，不能仅靠同名判断没变。
- `restores/`：恢复阶段及提交结果，支持同一请求的安全回读。
- `last-error.json`：最近一次定时执行错误，覆盖尚未生成历史记录的初始化失败。
- 每五分钟 Cron 唤醒一次，只有每天 04:00 创建新自动备份；其他唤醒用于分段处理、有限重试及每日一次保留策略清理。暂停自动备份不取消用户已经创建的备份任务。

ZIP 使用 STORE 格式流式输出，图片本身已经压缩。CRC 使用 Workers 支持的 `node:zlib.crc32` 在备份阶段预计算，下载时不再逐字节运行 JS 校验循环；浏览器验包不占用 Worker CPU。单张本站图片上限 8 MiB，数据清单上限 20 MiB，每包最多 400 张图片，标准 ZIP32 单包上限约 4 GiB；超限或缺图明确报错。导入按图片分别上传，避免整包上传请求体限制。

## 验证与发布

`npm run check`；`npm test` 包含构建、现有功能回归、真实本地 D1/R2 备份恢复、故障回滚、并发保护、鉴权隔离、ZIP 损坏与重复文件校验、客户端错误快照保留。

本次不新增/删除数据库表或列。按 GitHub PR → 检查通过 → 合并 master → Actions 部署的既有流程发布，根 `wrangler.jsonc` 同时发布 Cron。回退时回退此 PR 并重新部署；先关闭自动备份设置可暂停新自动任务，已生成的私有备份文件保留，不自动删除。
